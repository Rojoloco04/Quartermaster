How Quartermaster fits together

A personal agent running on one Windows machine. It shares one markdown vault and one Claude subscription across Discord, the terminal, a local dashboard and a few scheduled jobs. The model phrases and decides; plain Python fetches, checks and executes.

The system at a glance

Every request enters through a surface and becomes an agent turn under a profile. The profile decides which tools exist and which directory the Claude CLI runs in. Tools reach your data through MCP servers and the vault.

One DM, start to finish

What happens between sending the bot a message and its reply.

RouteThe bot sees a DM from the owner and picks the owner profile. "stop" and "start fresh" are handled in code.
Build the turnSonnet unless the message starts with opus: or haiku:; a fresh session after 5 idle minutes. Lessons and open conflicts are appended, read fresh.
Run Claudeclaude.exe starts with cwd = the vault and continues the shared session, so the terminal sees it too.
Every tool call checkedcheck_tool allows only the profile's tools and confines file access to the vault.
Reach your dataVault files directly; calendar, mail, tasks and Notion through MCP servers.
Stream backText arrives as it's written, with a live status line that's removed at the end. The whole turn is logged.

The security boundary

A prompt rule is not a boundary against someone who can send text, and emails and web pages are written by strangers. Containment is enforced three ways, because each alone has leaked once.

1
tools decides what existsA profile with an empty list has no built-in tools at all. (allowed_tools only pre-approves, which once left the full toolset reachable.)
2
dontAsk refuses anything not pre-approvedThe CLI also loads the account's claude.ai connectors (Gmail send, Drive share); none belong to any profile.
3
check_tool checks argumentsFiles and glob patterns stay inside the profile's directory; .claude/, .mcp.json, .git/ and the dev queue can't be written. Bash is never available over chat.

Moderation: the model parses, code executes. The model never holds a moderation tool, so channel text can at worst produce a plan a human declines.

model: English → OpsPlan→ invoker's real permission→ role hierarchy both ways→ match targets→ preview + confirm→ execute

Writes that need you. Notion pages other than the agent's own "Claude" page are only proposed; a Confirm button in Discord applies them. The dashboard's editors require the page's CSRF token and an expected Host header, and refuse a save if the agent changed the file since you opened it.

Memory: how it learns and stays consistent

Where knowledge comes from
  • Notion → pulled one way into notion/ daily or on request; pages deleted in Notion leave the mirror. Never edited in the vault.
  • Conversation → the agent writes facts/ (about you, plans, interests).
  • Corrections → record_lesson adds a rule to facts/lessons.md, read into every reply and digest.
  • The Claude page in Notion is the agent's own; it writes there freely.
How it stays true
  1. You say something changed. The agent fixes every file that states it in the same turn.
  2. Daily at 07:30, reconcile merges duplicates and drops dates that have passed, with backups.
  3. Disagreements it can't settle go to conflicts.md and to you as a question.
  4. You answer in plain words; the answer propagates to every file.

Three rules explain most of it: one source of truth per thing; mute is permanent and reminding is the default; markdown for what a person reads, SQLite for what the machine counts.

A day on the schedule

Windows Task Scheduler, while logged in. Each job is a fresh qm process; a failure is logged, never DM'd as noise.

05:00 08:00 11:00
05:00game backup
07:00Notion sync
07:30reconcile
08:00digest DM
Sun 09:00Claude page tidy

The digest is daily at digest.hour (weekly on Sundays if you prefer) and carries the on-sales of acts you like. Sync runs first, so the other jobs read a fresh mirror. Last, at 23:00, qm push commits the vault and pushes it to its private remote, which is its backup.
